## Proyectos

Este laboratorio se encuentra en su etapa inicial.

Los proyectos se incorporarán conforme tengan código disponible, documentación suficiente y resultados verificables.

Cada proyecto contará, cuando corresponda, con su propia documentación:

- **Objetivo:** qué problema busca resolver.
- **Tecnologías:** herramientas y dependencias utilizadas.
- **Estado:** experimental, prototipo, funcional o archivado.
- **Ejecución:** instrucciones para instalarlo y utilizarlo.
- **Limitaciones:** alcance actual y aspectos pendientes.

Los proyectos que requieran mantenimiento o despliegue independiente podrán desarrollarse en repositorios propios y enlazarse desde aquí.

## Filosofía de desarrollo

**La utilidad precede a la complejidad.**

El propósito es desarrollar herramientas que tengan una finalidad identificable.

1. **Problemas antes que herramientas.** La tecnología se elige en función del objetivo.
2. **Modularidad.** Construir componentes comprensibles, reutilizables y fáciles de mantener.
3. **Reproducibilidad.** Documentar procesos, dependencias y resultados.
4. **Verificación.** Distinguir entre hipótesis, prototipos y soluciones comprobadas.
5. **Aprendizaje continuo.** Experimentar, medir, corregir y documentar lo aprendido.

### Desarrollo asistido por IA

El repositorio utiliza instrucciones para trabajar con **OpenAI Codex**, con autonomía técnica ampliada dentro de cada tarea autorizada.

[`AGENTS.md`](AGENTS.md) establece las reglas generales. La skill [Gauntlet](.agents/skills/gauntlet/SKILL.md) define cómo construir, comprobar, auditar y corregir cambios relevantes. Puede solicitarse expresamente con `$gauntlet` en un entorno compatible.

La revisión se adapta al alcance y al riesgo. Cuando existen herramientas de delegación, un auditor separado examina los cambios; cuando no, se declara la autorrevisión. Estos archivos no crean un agente permanente ni modifican los permisos del entorno.

### Seguridad y control de versiones

- Git mantiene un historial verificable de los cambios.
- Las credenciales y los datos confidenciales no deben incorporarse al repositorio.
- Los cambios relevantes deben documentarse y comprobarse antes de integrarse.
- Publicar, desplegar o modificar sistemas externos requiere una autorización que cubra la operación.
